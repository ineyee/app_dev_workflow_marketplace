# Android 提测到蒲公英

## 适用范围

处理本地 Android 项目中的蒲公英提测请求：调用现有 `fastlane beta`，完成项目已配置的构建、上传和企业微信通知。

不处理 Google Play 发布、Git 提交、打 tag，也不替项目补写 Fastfile、脚本或发布配置。

## 工作流程

1. **确认项目**：在当前本地工作区检查项目根目录是否存在 `fastlane/Fastfile`，并确认其中定义了 `lane :beta`。找不到时说明阻塞原因，不跨项目猜测目标。
2. **收集说明**：
   - 用户未提供实质性更新说明时，先询问：`本次提测的更新说明（releaseNote）是什么？请直接分多行输入。`
   - 用户已提供说明时，保留原文、中文、标点和行顺序，不改写或补充内容。
3. **准备参数**：把用户输入的实际换行转换为两个字符 `\n`，以兼容现有 Fastfile 的换行处理；用户输入的字面量 `\n` 原样保留。不要把说明拼成 Ruby 表达式。
4. **执行 lane**：从项目根目录执行现有命令，确保整个 `releaseNote` 是一个参数：

   ```bash
   fastlane beta releaseNote:"1、修复已知 Bug；\n2、提升部分性能。"
   ```

   示例文案只用于说明格式，执行时必须替换为用户原文。对双引号、单引号、美元符号、反引号等字符进行安全参数转义；若执行工具支持 argv 数组，优先传入单个参数，避免 Shell 解释。无需创建辅助脚本。
5. **核对结果**：检查退出码和日志，分别报告构建、蒲公英上传、企业微信通知是否成功。后续阶段失败时停止，不自动重跑 `beta`，避免重复上传或通知。

## 运行约束

- 使用项目已验证可用的 `fastlane` 命令；不主动切换 Ruby、rbenv、Homebrew 或 Bundler 版本。
- 仅在项目根目录执行，不跨项目寻找发布目标。
- 不采用 Fastfile 中的默认更新说明替代用户输入。
- 不复制 `build`、`upload`、`notify` 的实现，也不另行调用这些 lane。
- Fastfile 可能含蒲公英 API Key 或企业微信 Webhook；不要把凭证写入 Skill、回复、临时脚本或日志摘录。
- 此 Skill 不负责安装 Fastlane、构建环境或签名环境；云端隔离环境无法直接操作用户 Mac 时，应明确说明限制。
