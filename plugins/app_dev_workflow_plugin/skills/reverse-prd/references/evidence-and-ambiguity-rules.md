# 证据、歧义与网络功能检查规则

## 证据引用

每条关键结论用 `E-*`：

```text
E-001 | verified-code | Classes/.../Controller.m | 类/方法或行段 | 命令/日期 | 支持“当前行为...”
E-002 | attachment-observed | screenshot.png | UI 区域 | 日期 | 支持“用户可看到...”
E-003 | session-confirmed | 会话第 N 轮 | 用户原话摘要 | 日期 | 支持“最终目标...”
```

代码/命令证明现状；用户最终确认决定目标；冲突时两者都保留，不能用现状替换目标。证据缺路径、方法或可观察区域时标 `unresolved`。`platform-equivalent` 必须同时给出两端证据和相同用户可观察结果；`external-unverified` 必须升级为 `unresolved/B-*`，不能单独支撑可执行需求。

## 阻塞问题

会改变 UI、开发或测试结果的缺口生成 `B-*`，并将文档标为 blocked：

```text
B-001 | 问题 | 影响 | 需要谁决定 | 解除条件 | 当前临时假设（如有）
```

典型阻塞：入口/状态冲突、成功/失败导航未定、翻译缺失、最低版本未定、接口参数无法确认、真机网络前置不可获得。不要用“后续确认”掩盖阻塞。

## Wi‑Fi/热点/设备连接检查表

没有证据的项写“未确认”，不要默认支持：

- 设备热点、手机个人热点、普通 Wi‑Fi 的角色/优先级；SSID 可见/隐藏、重复 SSID、WPA/WPA2/WPA3、空密码、密码错误；
- 手机未连 Wi‑Fi、已连目标 Wi‑Fi、蜂窝回退、网络切换、无互联网但局域网可用、Captive Portal；
- 设备与 App 未连接/连接中/已连接/断开中/断开后视频预览、音频源、媒体引擎、设备列表清理；
- Local Network、蓝牙、位置、网络配置/系统设置跳转的授权、拒绝、稍后授权、弹窗消失和设置返回；
- 加载、超时、取消、重试次数、重复点击、回调去重、页面销毁、前后台恢复；
- 系统/设备/路由器/安全类型矩阵、seed data 和真机前置；
- 日志不得记录 Wi‑Fi 密码、设备密码、token、raw payload，诊断字段必须脱敏。

## 需求演进裁决

后续用户说“改成/现在期望/不再/继续”时，更新同一最终条目并把旧条目标 `deprecated`。截图只改变 UI 事实，不能推翻文字确认。代码已实现某行为不代表 PRD 必须保留；需区分“已实现但本次废弃”和“保持兼容”。

## 验收最小字段

```text
CASE-001 | 引用 FR/UI/ERR/LOC/NFR | 环境 | seed data | 前置 | 步骤 | 预期 | 实际记录 | E-* | P0/P1/P2
```

网络用例写设备型号、系统版本、路由器/热点、SSID/安全类型、手机当前网络和 App/设备连接状态；否则只能算设计检查，不能算真机验收。

## 常见失败纠正

| 失败写法 | 纠正 |
|---|---|
| “按 iOS 实现” | 写平台无关的可观察状态，再列已证实集成契约 |
| “支持多语言” | 写每种语言的最终文案、key、占位符和验收 |
| “网络失败时重试” | 写触发错误、按钮、次数/时序和最终状态 |
| 把截图当协议证据 | 只记录 UI 观察，协议标 `unresolved` |
| 现状代码覆盖用户目标 | 演进账本保留目标，现状只写兼容/差距 |
| 先写文件再发现冲突 | 先证据清单和 `B-*`，未决则 blocked |
