# 根据 Figma 实现静态 UI

把设计实现为真实的 UI 元素，并以**像素级实现**为硬性验收标准。不能草率实现、凭截图猜测或用“差不多”的间距和样式代替设计规格。Figma 文件是布局和视觉规格的来源，不能把整页截图当作运行时界面。

## 触发与 Figma 链接前置条件

当用户明确要求编写 UI 代码，并使用以下表达或其近义表达时，应用本 skill：

- “写一下这个界面”
- “写一下这个控件”
- “实现一下这个界面”
- “实现一下这个控件”
- “按这个 Figma 做出来”“还原这个页面”“把这个设计实现出来”等

开始读取设计或编写代码前，先检查当前对话中是否已有 **Figma 节点 link**。有效链接应类似：

`https://www.figma.com/design/Q8LqiGQjKe2eTjZvsDuxP1/login?node-id=5-2&t=wMbrQSMMIRC9zt4A-4`

如果没有这类链接，或链接不包含可定位节点的信息，必须先提示用户：

> 请先输入 Figma 节点 link（例如：`https://www.figma.com/design/Q8LqiGQjKe2eTjZvsDuxP1/login?node-id=5-2&t=wMbrQSMMIRC9zt4A-4`），再开始实现。

在用户提供链接前，不要开始 UI 实现，不要凭截图、文字描述或经验猜测设计规格。收到链接后，再按下面流程继续。

## 必须遵循的流程

1. 使用 `figma-mcp-bridge` 读取目标节点及其子图层，收集边界、排版、颜色、填充、描边、效果、间距和相关资源。如果 bridge 不可用或无法读取目标节点，应说明阻塞原因并请求访问权限或导出文件；不能仅凭截图宣称已实现像素级还原。
2. 将每个可见图层映射为实现：文字使用文字组件，控件使用真实控件，简单形状和渐变用代码实现，图标使用矢量路径或独立图标资源。照片、插画和复杂纹理应按合适的尺寸导出为独立图片资源。
3. 先按“复用现有控件”规则检查项目，再使用项目已有的 UI 框架和布局约定实现。文字应保持可编辑；界面包含控件时应保留真实的交互行为。静态 UI 请求不等于授权凭空实现后端认证或导航流程。
4. Figma 整页截图只能用于视觉对照。**禁止把它作为运行时页面、全屏背景、WebView 图片，或在其上叠加透明控件。** 将同一张截图导出为 2 倍或 3 倍尺寸也不符合要求。
5. 在目标运行环境中验证结果：构建或渲染界面，在相同尺寸下与 Figma 节点截图逐项对照，修正尺寸、位置、字体、行高、颜色、圆角、阴影、间距和状态等差异，并检查源码和资源，确认运行时没有使用整页截图。未完成对照和修正前，不得宣称已经像素级实现；报告仍存在的视觉差异或无法取得的设计数据。

## 复用现有控件

复用检查应当**有限、就近、以明显匹配为止**，避免为了寻找一个控件进行无边界的全项目搜索。

1. 在创建某个控件前，依次查看：
   - 当前功能目录或当前页面附近的同类文件；
   - 项目已有的共享组件、UI 工具或设计系统目录；
   - 同一模块中 2–3 个明显同类的使用点。
2. 如果找到语义和用途相符的组件，即使需要通过参数或轻量样式适配，也优先复用。
3. 在上述范围内没有明显匹配时，立即创建新的控件，不继续扩大搜索范围。
4. 只有用户明确要求全局统一，或项目文档指定了组件来源时，才扩大为全项目搜索。

判断顺序：**已有同类组件 → 复用并适配；没有明显匹配 → 创建新的可复用组件。** 不要为了形式上的复用而扭曲组件语义或牺牲 Figma 的视觉规格。

## 资源边界

图片资源可以代表单独的视觉图层，例如照片、插画、Logo 或复杂纹理。图片不能包含页面的实时文字、表单、按钮或多个无关 UI 元素。如果 Figma 图层把装饰图和 UI 混在一起，应先分离装饰资源，再用代码重建 UI 部分。

## 常见错误

“截图能最快得到精确像素”不是使用截图作为界面的理由。这样会失去原生清晰度、可访问性、文字可编辑性、响应式能力和可靠的交互状态。截图只能用于比较。
